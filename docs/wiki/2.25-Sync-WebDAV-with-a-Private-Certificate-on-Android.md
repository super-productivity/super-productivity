# Sync WebDAV with a Private Certificate on Android

This guide shows how to make **WebDAV** or **Nextcloud** sync work on Android when your server uses a self-signed certificate or one from your own certificate authority (CA). If sync fails with _"the server's certificate is not trusted on this device"_, follow these steps.

Older releases show a raw "SSL error … Trust anchor" message instead of the explanation below; the steps work either way. Desktop and web use the operating system's or browser's certificate store and are not covered here.

## Why it fails

Android accepts the connection only if all of these are true:

- **The certificate was installed as a "CA certificate".** Certificates installed as a "VPN & app user certificate" (or "Wi-Fi certificate") are not used to trust servers.
- **The installed certificate is a CA** (`CA:TRUE` in its basic constraints). A plain self-signed server certificate without it cannot be installed as a CA certificate, so it can never be trusted.
- **The server certificate lists the address you sync to as a Subject Alternative Name (SAN)**: the host name (`DNS:`) or IP address (`IP:`) exactly as entered in the sync settings. The Common Name (CN) alone is ignored.
- **The server sends its intermediate certificates**, if any. Android does not fetch missing ones.
- **No certificate in the chain has expired**, and the device's clock is correct.

The reliable fix is a small private CA that signs your server's certificate.

## 1. Create a private CA

Run these commands on a computer with OpenSSL 1.1.1 or newer (`openssl version`). Replace `home.arpa` and `192.168.1.0/255.255.255.0` with your own domain and network.

```sh
openssl req -x509 -newkey rsa:3072 -sha256 -days 3650 -nodes \
  -keyout ca.key -out ca.crt -subj "/CN=My Home CA" \
  -addext "basicConstraints=critical,CA:TRUE,pathlen:0" \
  -addext "keyUsage=critical,keyCertSign,cRLSign" \
  -addext "nameConstraints=critical,permitted;DNS:home.arpa,permitted;IP:192.168.1.0/255.255.255.0"
```

The `nameConstraints` line limits the CA to your own domain (and its subdomains) and network, so even if `ca.key` leaks, it cannot be used to impersonate other websites to your phone. Keep `ca.key` private and off the server.

## 2. Create the server certificate

Replace `nas.home.arpa` and `192.168.1.10` with the host name and/or IP address you enter in Super Productivity. Both must fall inside the CA's name constraints.

```sh
openssl req -newkey rsa:3072 -sha256 -nodes \
  -keyout server.key -out server.csr -subj "/CN=nas.home.arpa"

cat > server.ext <<'EOF'
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=DNS:nas.home.arpa,IP:192.168.1.10
EOF

openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -days 825 -sha256 -extfile server.ext -out server.crt

cat server.crt ca.crt > fullchain.crt
```

Check the result:

```sh
openssl x509 -in server.crt -noout -ext subjectAltName
openssl verify -CAfile ca.crt -verify_hostname nas.home.arpa server.crt
```

The second command must print `server.crt: OK`. Note the expiry date and repeat this step before the certificate expires.

## 3. Configure the server

Point your web server at `fullchain.crt` (server certificate followed by the CA) and `server.key`. For example:

- **nginx:** `ssl_certificate fullchain.crt;` and `ssl_certificate_key server.key;`
- **Apache:** `SSLCertificateFile fullchain.crt` and `SSLCertificateKeyFile server.key`
- **Caddy:** `tls fullchain.crt server.key`

Restart the server, then check what it actually sends:

```sh
openssl s_client -connect nas.home.arpa:443 -servername nas.home.arpa \
  -verify_hostname nas.home.arpa -CAfile ca.crt </dev/null
```

The output must end with `Verify return code: 0 (ok)`.

## 4. Install the CA on Android

1. Copy `ca.crt` (not `server.crt`, not any key) to the phone.
2. Open **Settings** and search for **CA certificate**. The menu path varies by manufacturer, usually **Security** → **Encryption & credentials** → **Install a certificate** → **CA certificate**.
3. Confirm the warning and pick `ca.crt`. Android requires a screen lock for this.
4. In Super Productivity, run sync again.

Android may show a "network may be monitored" notice afterwards. That is expected for any user-installed CA.

## Alternatives

If you would rather not manage a CA:

- **Use a publicly trusted certificate.** [Let's Encrypt](https://letsencrypt.org/) certificates work on every device without installing anything. With a DNS-01 challenge the server does not need to be reachable from the internet. [Caddy](https://caddyserver.com/docs/automatic-https) obtains them automatically, and [Tailscale HTTPS](https://tailscale.com/kb/1153/enabling-https) issues them for your `*.ts.net` machine names.
- **Use SuperSync** instead of WebDAV. See [[2.08-Choose-Sync-Backend]].
