# Run with Docker

How to run Super Productivity pieces in Docker. There are three separate deployments; pick the one that matches what you need:

| You want to…                                                  | Deploy                                                                                    |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Sync the desktop or mobile apps through your own server       | **Sync only:** a self-hosted SuperSync server (no web app needed)                         |
| Also use Super Productivity in a browser served from your box | **Web app + sync:** the web app container, plus a sync backend reachable over the network |
| Sync through a WebDAV server you already run (e.g. Nextcloud) | **Existing WebDAV:** no server container; point the apps at your WebDAV server            |

To compare the sync providers themselves, see [[2.08-Choose-Sync-Backend]] and [[3.08-Sync-Integration-Comparison]].

## Sync only: self-host SuperSync

SuperSync is the sync server built for Super Productivity. It is still in **beta** (see [[3.08-Sync-Integration-Comparison]]).

The supported self-hosted setup today is:

- an **AMD64 (x86-64)** Linux host — the server image is published for `linux/amd64` only;
- a **domain name** that points at that host, with ports **80 and 443** free, so the bundled Caddy proxy can obtain an HTTPS certificate;
- a working **SMTP** account, because sign-up needs email verification;
- the **desktop (Electron), Android, or iOS** apps as clients.

Follow the [SuperSync server README](https://github.com/super-productivity/super-productivity/blob/master/packages/super-sync-server/README.md) — it is the single authoritative install recipe, including the client setup steps. LAN-only installs, running behind an existing reverse proxy, and ARM hosts are not covered by a tested recipe.

## Web app + sync

### Run the web app

```bash
docker run -d -p 8080:80 johannesjo/super-productivity:latest
```

Open [http://127.0.0.1:8080](http://127.0.0.1:8080). The image is published for `linux/amd64` and `linux/arm64`; Docker picks the one matching your host (use `--platform` to override).

**Where your data lives:** the web app keeps all tasks in **the browser's local storage on each device** (IndexedDB). The container stores nothing. That local copy is neither sync nor a backup: clearing site data, using a private window, or switching browsers or devices starts empty. Use a sync provider to share data between devices, and see [[4.23-Managing-Your-Data]] for backups.

**Same machine vs. other devices:** `http://127.0.0.1:8080` only works on the machine running the container. Other devices need an address they can reach, served over HTTPS. This guide does not provide a tested recipe for exposing the web app that way.

### Add sync

The web app talks to the sync backend from the browser, so the backend must accept that origin:

- **SuperSync:** set up the server as above, then add the web app's exact origin (e.g. `https://sp.example.com`) to the server's `CORS_ORIGINS` — see the server README.
- **WebDAV / Nextcloud:** the WebDAV server must send CORS headers for the web app's origin. Browsers can block WebDAV requests otherwise; the desktop app avoids this.

## Existing WebDAV or Nextcloud

If you already run Nextcloud or another WebDAV server, you do not need any extra container: configure **Nextcloud** or **WebDAV** in the app (see [[2.09-Configure-Sync-Backend]]). This is a valid choice for new installs too. Note that the generic **WebDAV** provider is itself labeled **experimental**, because WebDAV servers behave differently.

### Bundled WebDAV example (single-machine try-out)

The repository's `docker-compose.yaml` contains a small example that serves the web app and a WebDAV server from the same host. It is meant for trying things out on one machine, **not** as a validated production or multi-device setup: the bundled WebDAV server does not enforce the write preconditions the app relies on to detect concurrent uploads.

1. Copy the repo files to a folder (e.g. `sp/`):

   ```bash
   git clone https://github.com/super-productivity/super-productivity.git
   mkdir -p sp
   cp super-productivity/docker-compose.yaml sp/
   cp super-productivity/webdav.yaml sp/
   cd sp
   ```

2. Edit `webdav.yaml`: set usernames, passwords, and per-user directories under `/data` so user data is separate.

3. Start the stack. Name the two services explicitly — `docker-compose.yaml` also
   defines a `db` and a `supersync` service used only by the E2E test suite, which
   run in test mode and must never be started outside it:

   ```bash
   docker compose pull app webdav
   docker compose up -d app webdav
   ```

4. Open [http://127.0.0.1:8080](http://127.0.0.1:8080) for the app. In the app, set up sync with WebDAV base URL: `http://127.0.0.1:2345/`. This address only works on the same machine.

### Prefilled WebDAV settings

The web app container can prefill **WebDAV** defaults in the sync settings from environment variables: `WEBDAV_BASE_URL`, `WEBDAV_USERNAME` and `WEBDAV_SYNC_FOLDER_PATH` (setting any of these preselects WebDAV), plus `SYNC_INTERVAL` (minutes), `IS_COMPRESSION_ENABLED` and `IS_ENCRYPTION_ENABLED`. No other provider can be prefilled this way, and no passwords are prefilled. See `docker-compose.yaml` for an example.
