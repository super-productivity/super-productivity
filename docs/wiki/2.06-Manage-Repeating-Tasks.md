# Manage Repeating Tasks

For how repeat configuration works and when instances are created, see [[4.13-Repeating-Tasks]].

## Open the Recurring Task Dialog (add or edit)

**From a task:** Open the task (click it so the task detail panel opens on the right), select **Schedule**, then select **Repeat** in the Schedule dialog. The recurring-task dialog opens with the title **Make task recurring** (new) or **Edit recurring task** (existing). Repeat is available only for main tasks (not subtasks) that are not linked to an issue; tasks imported from Jira or Git cannot be recurring.

**From the scheduled list:** Go to the **Scheduled tasks** page (e.g. via **Shift+S** or the **Go to scheduled tasks** shortcut). In the **Recurring Tasks** section, each recurring task is shown as a card. Click the card (the line with the repeat icon and the recurrence text) to open the **Edit recurring task** dialog for that configuration.

You can also open the dialog from a repeating task instance or from a repeat projection on the Schedule or Planner (e.g. by clicking the repeat icon or the event).

## Create a New Repeating Task

1. Open a **main task** (not a subtask, not from an issue), select **Schedule** in the task detail panel, then select **Repeat**. The dialog title is **Make task recurring**. New copies keep the task's title.
2. In **Repeats**, choose a quick setting:
   - Every day
   - Every Monday through Friday
   - Every week on &lt;weekday&gt; (e.g. every week on Wednesday)
   - Every month on day &lt;date&gt;
   - Every year on &lt;day and month&gt;
   - After I complete it… — the next copy comes a set time after you complete the current one (see below).
   - Custom… — then use the extra fields (see below).
3. For **Custom** or **After I complete it…**, set:
   - **Repeat every** — a number (1–1000) and a **Unit**: Day, Week, Month, or Year (plural above 1).
   - For a fixed weekly cycle: under **Repeat on**, pick the days (Mon–Sun) on which the task should recur.
   - For a fixed monthly cycle: choose a **Monthly pattern**. **Day of month** uses the day shown in **Start date**; first, second, third, fourth, and last patterns also require a **Weekday**.
   - After completion there are no weekdays or monthly pattern: "every 2 weeks after I complete it" means 14 days after the day you complete it. Only one copy is open at a time; completing it (or marking it as won't do) starts the count for the next one.
4. Below the rule, click the **Start date** field (shown as **First one on** after completion) to pick the first day and, optionally, a time (leave it blank for an all-day task) and a reminder.
5. Next to it, optionally set **Ends on** (an optional end date; see below).
6. In **Options**, first how the series behaves: **If you fall behind** (see below) and **Paused**. Then what new copies get: **Tags**, **Priority** (None, Low, Medium, or High), **Default estimate**, **Default notes**, **Inherit subtasks** (copy subtasks from the latest instance to the next), and, if inherit is on, **Disable auto-updating subtasks** (do not update inherited subtasks when the newest instance changes).
   **If you fall behind** has three choices; the text below it describes the picked one:
   - **Keep every copy** — a new copy is added on each date, even if earlier ones are still open.
   - **Only keep the latest** — dates missed while the app was closed are skipped, and older copies you haven't touched are removed when a newer one appears. This is the default for the **Every day** preset (or an equivalent custom every-single-day cycle); see [[4.13-Repeating-Tasks]].
   - **Wait until the current one is done** — the next copy is added once you complete the current one or mark it as won't do.

   A line below the start and end dates shows the next dates a fixed schedule falls on (for example "Falls on: Wed, Jun 10 · Mon, Jun 15 · Wed, Jun 24"), followed by a fall-behind choice other than the default. When there are no dates to show, it states the rule instead if a policy needs saying, e.g. for a paused series. It appears when it says more than the preset, e.g. for a custom rule, an end date, a non-default fall-behind choice, or a paused series.

7. Click **Save**. New instances are created according to the pattern when you open the project or the app.

## Add a time and Reminder to a Repeating Task

1. Open the recurring task config (task detail panel → **Schedule** → **Repeat**, or scheduled list → click the recurring task card).
2. Click the **Start date** field below the rule and set a time (e.g. 15:00). Leave it blank for an all-day task.
3. When a time is set, choose when to be reminded (e.g. when it starts, 5 minutes before it starts), then confirm.
4. Click **Save**.

## Set a Default time Estimate for Instances

In the recurring task dialog, open **Options** and set **Default estimate** (duration). New instances will use this estimate unless you change it per task. Click **Save**.

## Stop a Recurring Task at an End Date

1. Open the recurring task config (task detail panel → **Schedule** → **Repeat**, or scheduled list → click the recurring task card).
2. Next to the start date, set **Ends on** to the last day the schedule should produce instances. The date cannot be before the **Start date**.
3. Click **Save**.

The end day is inclusive: an occurrence falling on it is still created. Until then nothing changes — instances appear as before. Clear the field to make the schedule indefinite again.

After the end day has passed, no new instances are created. Instances that already exist are kept as they are, including the current live instance (finish or delete them separately). A window that contains no matching day at all — e.g. a Monday-only schedule whose first Monday falls after the end day — never creates an instance and leaves the task on its current day; see [[4.13-Repeating-Tasks]].

## Pause a Recurring Task

1. Open the recurring task config (task detail panel → **Schedule** → **Repeat**, or the **Recurring tasks** panel of its project → click the recurring task).
2. In **Options**, check **Paused** and click **Save**. No new copies are added while it is paused; copies that already exist stay as they are.
3. To resume, uncheck **Paused** and click **Save**. Dates that passed while it was paused are not added afterwards, and an open copy stays on its date. If today is one of its days, today's copy appears right away.

## Add Tags to a Recurring Task Configuration

In the dialog, open **Options** and use **Tags** to add one or more tags. New copies get these tags. Click **Save**.

## Inherit Subtasks in New Instances

1. Open the recurring task config.
2. Enable **Inherit subtasks**. The description explains that subtasks from the most recent task instance will be recreated with the recurring task.
3. Optionally enable **Disable auto-updating subtasks** so that when you change the template subtasks on the newest instance, existing instances are not updated automatically.
4. Click **Save**.

## Edit a Recurring Task Configuration

Open the config (task detail panel → **Schedule** → **Repeat**, or from the **Recurring Tasks** section on the scheduled list by clicking the card). Change **Task title** (new copies take the series title; renaming one copy renames only that copy), **Repeats** and the rule, **Start date** (with its time and reminder), **Ends on**, or anything under **Options**. Click **Save**.

Below the repeat rule, the dialog shows when the next instance will be created, and, if **Inherit subtasks** is on, the subtasks it will get (in **Options**, below that option). After a schedule change, or after turning **Inherit subtasks** on, the preview updates once you save.

## Skip a Single Future Date

1. In the **Planner**, click the faded repeat projection on the future day you want to skip. The **Edit recurring task** dialog opens for that date.
2. Click **Skip for &lt;date&gt;** (at the left of the dialog's buttons, next to **Remove**) and confirm. Only that date is skipped; the repeat configuration and other instances are unchanged.

The button appears only for a date after today.

## Delete the Entire Recurring Task (stop All Future instances)

1. Open the **Edit recurring task** dialog.
2. Click **Remove** (at the left of the dialog's buttons, apart from **Cancel** and **Save**). This removes the repeat configuration. Future instances will no longer be created; existing task instances remain until you delete them separately.
