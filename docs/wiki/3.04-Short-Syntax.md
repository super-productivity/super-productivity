# Short Syntax

Super Productivity supports six main short syntax forms for quickly adding metadata to tasks: tags (`#`), projects (`+`), time estimates (`m`/`h`), due dates (`@`), deadlines (`!`), and priority (`p1`–`p3`). The due date form also accepts recurrence phrases (`@every friday`, `@daily`) in the Add Task Bar. The forms are controlled in [[3.02-Settings-and-Preferences#short-syntax]], with a separate opt-in setting for deadline syntax and a setting to switch priority syntax off.

## Supported Syntax Forms

### Tag Syntax (`#`)

- **Symbol:** `#`
- **Purpose:** Add tags to the task.
- **Grammar:** `#<tag-name>`. A space is required before `#`.
- **Parameters:** Tag name (case-insensitive).
- **Valid:** `"Task #urgent"`, `"Meeting #work #important"`. Multiple tags allowed.
- **Invalid:** `"Task#urgent"` (no space before `#`) — the whole short-syntax run returns no changes. If other tokens are valid (e.g. `"Task#urgent #other"`), only the valid tag is applied and the invalid token is left in the title.

### Project Syntax (`+`)

- **Symbol:** `+`
- **Purpose:** Assign the task to a project.
- **Grammar:** `+<project-name>`. A space is required before `+`.
- **Parameters:** Project title or partial title; minimum 3 characters. Matching is prefix-based, case-insensitive, with spaces removed for comparison. The shortest matching project title is preferred when several match.
- **Valid:** `"Task +Important Project"`, `"Task +Project"` (partial match). Project names containing `+`, `#`, `@`, or similar are supported; the parser uses lookahead so these characters inside the name do not end the token.
- **Invalid:** `"Task+Project"` (no space before `+`) — no project is applied.

### Time Estimate Syntax

- **Symbols:** `m` (minutes), `h` (hours). Optional prefix `t`. Optional `/` to separate time spent from time estimate.
- **Purpose:** Set time spent and/or time estimate.
- **Grammar:** `[t]<number><unit>[ <number><unit>...][/ <number><unit>...]`. Units: `m`, `h`. Decimal numbers allowed (e.g. `1.5h`). Before `/`: time spent on the current day. After `/`: time estimate. Clusters like `1h 30m` are supported.
- **Parameters:** Time spent (before `/`): e.g. `30m`, `1.5h`. Time estimate (after `/`): e.g. `1h`, `90m`. One side can be omitted: `30m/` sets only time spent; `1h` sets only estimate.
- **Valid:** `"Task 10m"`, `"Task 1h/2h"`, `"Task 30m/"`, `"Task t1.5h"`, `"Task 1h 30m / 2h"`.
- **Defaults:** `h` = 60 minutes.

### Due Date Syntax (`@`)

- **Symbol:** `@`
- **Purpose:** Set due date/time for the task.
- **Grammar:** `@<date-time-expression>`. No space is allowed between `@` and the expression.
- **Parameters:** Date/time expressions supported by the Chrono-based parser (e.g. `4pm`, `friday`, `tomorrow 19:00`, `2030-10-12T13:37`), plus the nth-weekday form below.
- **Valid:** `"Task @4pm"`, `"Task @friday"`, `"Task @tomorrow 19:00"`, `"Task @2030-10-12T13:37"`.
- **Invalid:** `"Task @ tomorrow"` (space after `@`) — due date is not applied and the expression is stripped from the title. Two-digit years 50–99 are corrected to the current or next calendar year to avoid Chrono interpreting them as years (e.g. `90m` in a date context).
- **Languages:** English always works. If the app language is one of the following, its date words work too: Chinese (Simplified and Traditional), Dutch, Finnish, French, German, Italian, Japanese, Portuguese (including Brazilian), Russian, Spanish, Swedish, Ukrainian and Vietnamese. For example, with German selected, `@morgen 15 Uhr` and `@tomorrow 3pm` both work. Other languages are not recognized: `@morgen` is not a date with an English or French app language, so a word that names a date in another language is never taken out of the title. A short date word of the app language (three letters or fewer) counts only right after the `@`: with German selected, `@so` is Sunday, but the `so` in `max@firma.de so bald` stays in the title. Longer dates may follow a leading article or preposition (`@le 5 mars` with French, `@um 15 Uhr` with German). When English and the app language both find a date, the reading that starts earlier, or is longer, wins (with German selected, `@tomorrow 3pm` is tomorrow at 15:00, not today); on a tie the app language wins (with French selected, `@mar 3` is Tuesday at 3:00, not March 3). Some languages cover fewer phrases than English; for example, Swedish does not combine a day word with a time (`@idag 18:00` sets today and leaves `18:00` in the title). A number followed by `h` or `m` is always a time estimate, so write the French `@demain 18h` as `@demain 18:00`.
- **Date order:** A numeric date that could be read either way, such as `@3/1`, follows the day/month order of **Datetime format locale** ([[3.02-Settings-and-Preferences#localization]]). With a day-first format (e.g. en-GB `DD/MM/YYYY`, German `DD.MM.YYYY`), `@3/1` is 3 January and `@03-01-2027` is 3 January 2027. With a month-first or year-first format (en-US `MM/DD/YYYY`, ISO 8601 `YYYY-MM-DD`, Japanese, Chinese), `@3/1` is March 1. The date format, not the app language, decides this for every app language, because an English app language does not say whether you write dates the US or the British way. A date that only works one way (`@25/4`) is read that way with either setting, and `@2027-03-01` is always March 1. Month names are read the same with either setting: `@dec 24` and `@24 dec` are both 24 December.
- **Nth weekday:** `@<n><weekday>` sets a one-off date on the nth occurrence of a weekday counting from today. `n` is 1–5, where 1 is the next occurrence, so `@1monday` is the same as `@monday`; `@2monday` is the Monday after next and `@4tuesday` is the fourth Tuesday. Weekday names may be full, abbreviated or plural and are case-insensitive (`@2mon`, `@2Mondays`, `@4TUE`). Whitespace between the number and the name is allowed for a single digit 1–5 (`@2 monday`); any other spaced number is not an nth weekday and goes to the regular date parser (`@10 fri` is Friday 10:00). An optional time can follow (`@2monday 3pm`); without one the task is scheduled as an all-day due date, like `@monday`. A date after the token (`@2friday tomorrow`) is not used and stays in the title. An `n` outside 1–5 (`@0monday`, `@9monday`) still consumes the token but sets no date, so the weekday is not left behind in the title. This is a plain due date, not a recurrence — use `@every 2 fridays` to repeat.
- **Nth weekday valid:** `"Task @2monday"`, `"Task @4tuesday"`, `"Task @2monday 3pm"`.
- **Same-day weekdays:** Without a time, `@1monday` entered on Monday after noon selects the following Monday, matching `@monday`. With an explicit time, it selects the following Monday once that time has passed. An occurrence exactly at the current time stays on the current day. Higher counts continue from that first occurrence, so on a Monday afternoon `@2monday` is the Monday after next Monday. The same rules apply to `!1monday` and `!2monday` deadlines.
- **Nth weekday times and daylight saving:** A clock change today does not discard a valid time on the requested weekday. If the requested time itself falls in a skipped interval on the target date, it moves forward by the clock change, matching the date/time picker (for example, 02:30 becomes 03:30 during a one-hour spring-forward gap). This also applies to nth-weekday deadlines.

### Recurrence Syntax (`@every ...`, `@daily`, ...)

- **Symbol:** `@`, shared with the due date form. A recurrence phrase must come directly after the `@`.
- **Purpose:** Create the task as a repeating task, equivalent to picking a repeat preset in the Add Task Bar's repeat menu.
- **Language:** Recurrence phrases are English only, whatever the app language. A time after the phrase can be in the app language (`@every friday 15 Uhr`).
- **Grammar:** `@every <unit>`, `@every <number> <unit>`, or a bare frequency word: `@daily`, `@weekly`, `@monthly`, `@yearly`, `@annually`. Units for `every`: `day(s)`, `week(s)`, `weekday(s)`/`workday(s)`, `month(s)`, `year(s)`, a weekday name (`friday`, `fri`, `fridays`, ...), or a day of the month (`15th`). A number may precede `day(s)`, `week(s)`, `month(s)`, `year(s)` or a weekday name, and must be between 1 and 999. An optional time can follow: `@every friday 3pm`.
- **Mapping:** `@every friday` → weekly on Friday (due date set to the next Friday); `@every weekday` → Monday through Friday; `@every 15th` → monthly on the 15th (due date set to the next 15th); `@daily 6am` → daily with a start time. The unanchored words recur on the day you add the task: `@weekly` on today's weekday, `@monthly` on today's day of the month, `@yearly` on today's date. If a time you add has already passed today, the first occurrence moves a whole period ahead so the recurring day stays the same — `@weekly 6am` added on a Wednesday at 10:00 is due next Wednesday, not tomorrow. `@every weekday` never starts on a weekend: `@every weekday 6am` added on a Friday at 08:00 is due Monday.
- **Intervals:** `@every 2 weeks` creates a custom recurring config repeating every 2 weeks on the day you add the task; `@every 3 days` repeats every 3 days from that day; `@every 2 fridays` repeats every 2 weeks on Friday, starting with the next one. The interval is editable afterwards in the repeat config dialog. An interval of 1 (`@every 1 week`) is the same as leaving the number out. `@every 2 weekdays` is not supported — every other workday is not a weekly schedule — and is parsed as a plain due date.
- **Valid:** `"Water plants @every friday"`, `"Journal @daily 6am"`, `"Pay rent @every 15th"`, `"Review @every 2 weeks"`, `"Water plants @every 2 fridays"`.
- **Scope:** Only in the Add Task Bar (task creation). In title edits of existing tasks the phrase is parsed as a plain due date, since an existing task cannot be converted to a repeating task this way. The parsed repeat shows on the repeat button and can be cleared there, which also removes the phrase from the input.

### Deadline Syntax (`!`)

- **Symbol:** `!`
- **Purpose:** Set a deadline date/time for the task.
- **Default:** Disabled. Enable deadline short syntax in the global Short Syntax settings to use it.
- **Grammar:** `!<date-time-expression>`. A space is required before `!` when it is not at the start of the title.
- **Parameters:** Date/time expressions supported by the Chrono-based parser (e.g. `14:30`, `friday`, `next month`), including the nth-weekday form described under Due Date Syntax (`!2monday`). The languages and date order are the same as for due dates.
- **Valid:** `"Task !14:30"`, `"Task !friday"`, `"Task @monday !friday"`, `"Task !2monday 3pm"`.
- **Invalid:** `"Done!"` (no space before `!`) — the exclamation mark is treated as punctuation and no deadline is applied.

### Priority Syntax (`p1`–`p3`)

- **Symbol:** none; the token is the whole word `p1`, `p2` or `p3`.
- **Purpose:** Set the task's priority.
- **Default:** Enabled. Switch off priority short syntax in the global Short Syntax settings to keep `p1`–`p3` in titles.
- **Grammar:** `p<1-3>` as a whole word: at the start of the title or after whitespace, and followed by whitespace or the end of the title. Lowercase only: `P1` is left in the title. It can appear anywhere in the title.
- **Mapping:** follows Todoist, where `p1` is the most important: `p1` → High, `p2` → Medium, `p3` → Low.
- **Valid:** `"Fix login bug p1"`, `"p2 Write report"`, `"Fix login bug #work @tomorrow p1"`.
- **Not a priority:** `"Convert mp3 files"`, `"Read chapter p10"`, `"Fix bug p1."` (punctuation attached), `"Task #p1"` (a tag named `p1`), `"Fix P1 incident"` (uppercase). These are left in the title unchanged.
- **`p4`:** not a token and stays in the title. In Todoist `p4` means "no priority", which is what a new task already has; clearing an existing priority is done from the task's context menu.
- **Several tokens:** all of them are removed from the title and the last one wins (`"Fix p3 login p1"` is High).
- **Issue tasks:** not parsed, so imported titles like `"p1 crash on save"` keep their text and get no priority.
- **Project names:** priority is parsed before projects, so a `p1`–`p3` word inside a project name is taken as priority (`"+Sprint p2"` sets Medium and only `+Sprint` is left to match a project).

## Formal Grammar and Regex Patterns

The parser uses regular expressions for each syntax form. Time: optional `t` prefix, digits and decimal with `m`/`h`, optional `/` for spent/estimate. Project: `+` with lookahead so delimiters (`#`, `@`, time-like tokens) inside the project name do not terminate the match. Tag: `#` followed by characters until a special character or whitespace. Due: `@` followed by characters until a special character. Deadline: `!` followed by characters until a special character. Priority: lowercase `p1`, `p2` or `p3` delimited by whitespace or the title's start/end. Nth weekday: `<digits><weekday>` at the start of a due/deadline expression. Exact patterns are defined in `short-syntax.ts` (e.g. `SHORT_SYNTAX_TIME_REG_EX`, `SHORT_SYNTAX_PROJECT_REG_EX`, `SHORT_SYNTAX_TAGS_REG_EX`, `SHORT_SYNTAX_DUE_REG_EX`, `SHORT_SYNTAX_DEADLINE_REG_EX`, `SHORT_SYNTAX_PRIORITY_REG_EX`, `SHORT_SYNTAX_NTH_WEEKDAY_REG_EX`).

## Default Values and Behavior

- **Time units:** `m` = minutes, `h` = 60 minutes.
- **Time spent only:** e.g. `30m/` sets time spent on the current day and no estimate.
- **Time estimate only:** e.g. `1h` sets estimate without time spent.
- **Date parsing:** Uses a custom Chrono-based parser for English plus the app language, with year correction for two-digit years 50–99 (current/next year). The day/month order of numeric dates follows the datetime format locale.
- **Project matching:** Prefix-based, case-insensitive, spaces removed; shortest matching project title wins.
- **Tag mode:** `combine` (default) or `replace`; configurable in settings.

## Where Short Syntax Is Supported

**Supported:**

- Add Task Bar (primary place for creating tasks with short syntax).
- Task creation when adding new tasks (e.g. via the shared add-task action).
- Task title updates when the only change is the title (syntax is re-parsed). A priority token in the edited title replaces the task's priority and is removed from the title; a title without one leaves the priority unchanged.

**Unsupported or disabled:**

- **Issue-linked tasks:** Tasks linked to external issues cannot use project, deadline or priority syntax (see [[2.07-Manage-Task-Integrations]]).
- **When disabled:** Disabled short syntax forms are ignored. Deadline and priority syntax have their own settings; deadline syntax is disabled by default, priority syntax is enabled.
- **Archived or hidden projects:** Project syntax does not match archived or hidden projects.
- **Content from outside the app:** Titles of tasks created from the Android and iOS share sheet, the `create-task` URL scheme action, dropped emails and AI assistant capture are stored literally; no short syntax in them is applied (`#`, `@`, `+`, `!`, `p1`–`p3`, time estimates).

## Parsing and Evaluation Rules

1. **Order of processing:** Priority → Time/due → Deadline → Project → Tag. Priority runs first so a due expression never reads the digit of `p1` as an hour.
2. **Title cleanup:** Parsed syntax is removed from the task title after processing.
3. **Tag creation:** Tags that do not exist yet are collected in a `newTagTitles` array for creation.
4. **Return value:** The `shortSyntax()` function returns an object with task changes (and `newTagTitles`, `remindAt`, `projectId`, `repeat`) or `undefined` if nothing was parsed or syntax is disabled.
5. **Buttons win over text:** picking a date, deadline, estimate or recurrence in the Add Task Bar's buttons removes the matching syntax from the input, the same way the buttons' clear (`x`) does, so the text stops advertising a value the task will not get. Changing the date of a task whose recurrence came from syntax keeps the recurrence and re-anchors it to the new date.

## Error Handling

**Malformed syntax:**

- Invalid syntax is ignored; the function may return `undefined` or only apply valid parts.
- No exception is thrown; invalid tokens are skipped or left in the title as appropriate.
- If a syntax type is disabled in settings, that form is not processed.

**Edge cases:**

- Project names containing `+`, `#`, `@`, or time-like patterns are handled so that the project token is parsed correctly.
- Two-digit years 50–99 in date expressions are corrected to the current or next year.
- Time estimate tokens (e.g. `90m`) in the same title as date expressions are parsed separately so Chrono date parsing does not consume the time estimate.

## Add Task Bar Behavior

- **Toggle new task position:** A toggle in the Add Task Bar controls whether the new task is added at the top or the bottom of the list.
- **Autocomplete:** The Add Task Bar can suggest tags, projects, and date expressions while typing. Priority has no trigger character and no suggestions.
- **Inline highlighting:** Detected short syntax (tags, project, estimate, due/deadline dates, recurrence, priority, extracted URLs) is highlighted directly in the input while typing, showing which characters will be stripped from the title before the task is created.

## Notes

- Short syntax is processed by the `shortSyntax()` function; it returns task changes or `undefined` when no changes are needed.
- The syntax forms are controlled by the global Short Syntax settings in [[3.02-Settings-and-Preferences]]. Deadline syntax is disabled by default; priority syntax is enabled by default.
