# Ожидаемый обработчик выхода плагина

`onBeforeAppClose(handler | null): Promise<boolean>` доступен в `plugin.js` и
смонтированном iframe. Он регистрирует один callback на экземпляр исполнения.
Повторная регистрация заменяет callback. `null` снимает регистрацию. Electron
возвращает `true`, браузер — `false`. В старом host метод может отсутствовать;
плагин должен проверить его наличие.

## Порядок выполнения

```text
Запрос выхода → обычные before-close участники → plugin finalizers → закрытие
                    sync и подтверждение
```

`ExecBeforeCloseService` сохраняет IDs до передачи уведомления подписчикам.
Финализаторы начинаются после подтверждения всех обычных участников через
`setDone`. Снятый обычный участник перестаёт блокировать эту фазу. Если пользователь
отменяет выход в finish-day диалоге или открывает дневную сводку, соответствующий
участник отменяет текущую попытку в coordinator без native DONE. Последующее
изменение настроек и снятие обычного участника не возобновляют отменённую попытку.
Новый явный запрос выхода создаёт новую попытку. Сворачивание окна,
скрытие вкладки и сворачивание в трей не запускают этот API.

Для main process используется один внутренний `PLUGIN_BEFORE_CLOSE_ID` и прежние
REGISTER/UNREGISTER/BEFORE_CLOSE_DONE. Плагин не получает произвольные IPC-методы.
Callback не является подтверждением успешной синхронизации: штатная sync может
завершиться обработанной ошибкой. Для удаления внешних данных плагин самостоятельно
проверяет свой опубликованный запрос и согласованный снимок.

## Срок и продолжение

Все финализаторы работают параллельно в общем окне 15 секунд. Срок начинается
после обычных участников. Callback получает `{ deadlineAt, signal }`:

- `deadlineAt` — абсолютное время Unix в миллисекундах;
- `signal` — локальный `AbortSignal`, который host отменяет при истечении срока,
  снятии регистрации или завершении фазы;
- отказ, исключение или promise без завершения не удерживают plugin ID после
  истечения срока. Это ограничение фазы плагинов, а не всего штатного sync/диалога.

```js
const supported = await plugin.onBeforeAppClose?.(async ({ deadlineAt, signal }) => {
  await saveDurableJob();
  while (!signal.aborted && Date.now() < deadlineAt) {
    const operation = await nextRevalidatedOperation();
    if (!operation || signal.aborted || Date.now() >= deadlineAt) break;
    await performOperation(operation, { signal });
  }
});
```

Пример описывает контракт; функции очереди предоставляет сам плагин. Он сохраняет
намерение до сетевого действия. Отмена fetch не доказывает, что сервер не выполнил
уже отправленный DELETE. После запуска приложения плагин проверяет состояние и
продолжает незавершённую операцию. Сотни файлов не требуют ожидать завершения всей
очереди перед выходом.

Ожидание promise не прерывает синхронный бесконечный цикл в renderer. Сбой процесса,
принудительное завершение и отключение питания не гарантируют вызов callback.
В браузере host не пытается ожидать сеть на unload и не заменяет выход событием
`visibilitychange`. Продолжение очереди при следующем запуске реализует плагин.

## Direct и iframe

Фоновый callback работает, даже когда страница плагина закрыта. Его регистрацию
снимает `PluginRunner` при teardown и ошибке инициализации. Runner удаляет API и
ready/unload callbacks; вызовы устаревшего API игнорируются.
Регистрация iframe живёт только до уничтожения этого iframe, включая навигацию и
закрытие встроенной панели. Для работы без открытой страницы нужен `plugin.js`.

Функция и AbortSignal не пересылаются через structured clone. Iframe сохраняет
callback локально. Host proxy передаёт request ID и deadline, затем ожидает
отдельный BEFORE_CLOSE_RESULT. Ответ проверяется по source, token, generation и
request ID. Host устанавливает listener до отправки события. Обычные API-вызовы
iframe продолжают обрабатываться во время callback, поэтому callback может
ожидать, например, `getTasks()` или `loadPersistedData()`.

Регистрация подтверждается сразу. Она не ожидает будущего выхода через обычный
30-секундный API timeout. Сам callback имеет отдельный абсолютный срок и событие
отмены; teardown удаляет listeners и ожидающие proxy. Семантика прежнего
`onUnload` остаётся синхронной с не ожидаемым результатом.

## Проверки

Целевые Angular specs: `before-close-coordinator.spec.ts`,
`plugin-before-close.spec.ts`, `plugin-before-close-iframe.spec.ts`,
`plugin-api.spec.ts`, `plugin-runner.spec.ts`,
`plugin-index.component.spec.ts`, `sync-effects-routing.spec.ts` и
`finish-day-before-close.effects.spec.ts`. Они проверяют порядок, отмену выхода,
deadline, teardown, вложенные API-вызовы и границу iframe. Проверка реального
Electron quit требует отдельной изолированной приёмки.
