# Product video guidance

Use this with the parent [E2E guide](../AGENTS.md). Start with the current [video README](README.md) for variants and commands, the relevant scenario in [scenarios/](scenarios/), and the shared [video-kit guide](../video-kit/README.md). `e2e/video-kit/` owns reusable captions, cards, cursor, camera, transitions, and recording. This directory owns app-specific seed, profiles, scenarios, [logos.ts](logos.ts), and [helpers.ts](helpers.ts). There is no `overlays.ts`.

Keep visible interactions on real controls and assert their results. [helpers.ts](helpers.ts) provides `hold` for editorial pacing, `dispatch` for covered state preparation, and `enableAnimations` because the screenshot seed disables animations. A video hold makes a moment readable; it is not a readiness check. Use `expect` or a locator wait to establish readiness. This differs from ordinary E2E tests, where arbitrary timing waits are undesirable.

The [fixture](fixture.ts) records from context creation, imports the screenshot seed through the app, and installs the Playwright page clock. Call `markBeatsStart()` after seed import and setup; the successful capture writes a trim sidecar beside its exact recording. Build uses that recording and metadata. Do not seed IndexedDB from `addInitScript`: import timing can race the app's database read. Let the recorded pre-roll be trimmed.

The installed page clock freezes page timers and `requestAnimationFrame`; advance it with `page.clock.runFor()` or resume it when timers or animated counters need to move. CSS transitions can still run while it is paused. Use [cutToScene](../video-kit/transitions.ts) or `nextScene` for app state preparation behind black. If showing a caption or card inside a `cutToScene` callback, pass `{ noWait: true }` so its fade plays during the reveal. Mark uncropped cuts with `markScene` for the contact sheet. Keep the static app zoom and seeded right-panel width in [fixture.ts](fixture.ts) consistent with layout; use the video-kit camera for motion rather than animating layout zoom.

For iteration, follow the [README's capture and `VIDEO_QUICK=1` build steps](README.md#adding-a-reel), inspect the contact sheet and MP4, then make a full build when publishing WebM/GIF. Run `npm run video:kit-test -- --workers=1` when changing shared primitives or recording/build metadata, and `npm run checkFile <filepath>` for each modified TypeScript file. A capture still needs the app and FFmpeg/ffprobe.
